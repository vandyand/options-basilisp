# Feature Parity Scope

This document separates the different meanings of "feature parity" in the
current system. A single report cannot prove parity across every strategy
because not every strategy uses the same feature stack.

## Scope A: Steve V2 Model Stack

Strategies:

- `strategy/steve-v2/chestnut/v1`
- `strategy/steve-v2/lynx/v1`
- `strategy/steve-v2/moose/v1`
- the paired long/short OAK/DOLPHIN routes generated by `launch_steve_six.lpy`

Feature stack:

- Old Python `scripts_5yr.live.feature_engine.FeatureEngine`.
- `918` raw tabular features.
- Live Greeks grid history.
- Corrected model bundles:
  - `live_model_chestnut_multihead_corrected`
  - `live_model_lynx_multihead_corrected`
  - `live_model_moose_multihead_corrected`
- Runtime neutralization from `neutralize_features.json`.

Current status:

- Active zero-filled aggregate features: `0`.
- Active degenerate aggregate features: `0`.
- Persistent active suspicious aggregate features: `37`.
- Deep-dive classification: `36` raw price-level nonstationary, `1`
  low-vol/regime-or-scale.
- Source evidence: SPY bid/ask close tracks captured SPY close, and bid/ask
  close are equal because live Alpaca stock bars are OHLCV bars, not quote bars.
- Status: improved but not fully passed. Raw price-level features still move
  predictions enough to require explicit remediation or acceptance.

## Scope B: Vol/Calendar/Condor Sim Strategies

Strategies include:

- `strategy/sim-vol/condor-rv/v1`
- `strategy/sim-term/calendar-slope/v1`
- related vol-term variants from `launch_vol_term_sim.lpy`

Feature stack:

- Basilisp `feature.core`.
- Chain-derived features such as `:feature/condor-mid-credit` and
  `:feature/calendar-straddle-slope`.
- Market slice and option-chain facts.

Current status:

- The Steve-v2 918-feature reports do not apply to these strategies.
- These need separate parity checks against option-chain snapshots, selected
  strikes/expiries, mid-price construction, and term-slope/condor-credit
  calculations.

## Scope C: Local Sim Fleet Bar Strategies

Strategies include local SMA, z-close, and canary variants from
`launch_local_sim_fleet.lpy`.

Feature stack:

- Simple Basilisp bar-derived signals and synthetic/canary features.
- No Steve-v2 918-feature vector.

Current status:

- The Steve-v2 feature reports do not apply.
- Required parity checks are simpler: market-bar completeness, warmup
  sufficiency, no warmup trading, deterministic signal replay, and source-bar
  equality.

## Required Gates

Steve V2 gate:

- No active zero-filled features.
- No active nonfinite features.
- No active degenerate features unless proven to be partial-session-only.
- Prediction-delta impact of suspicious active features is below a declared
  threshold or explicitly accepted.
- Raw price-level features are either transformed/retrained/pruned or accepted
  as intended regime context.

Vol/calendar/condor gate:

- Option-chain snapshot coverage by timestamp.
- Underlying price used for strike selection matches the market-bar source.
- Selected strikes/expiries match replay.
- Leg mid-price construction matches replay.
- Feature values match replay to tolerance.

Local sim bar-strategy gate:

- Source bars match replay.
- Warmup observations cannot trade.
- Signal values and decisions are deterministic under replay.
